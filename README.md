# notion-project-logger

> Notion "프로젝트 관리 템플릿" 기반 프로젝트에서 업무 등록·진행 관리·완료 정리·작업 일지를 대신 맡는 Claude 스킬

이 템플릿은 **업무 DB 하나 + 업무 로그 DB 하나 + 자료실 폴더 구조**로 이루어져 있고, 새 팀 프로젝트마다 복제해서 씁니다. 복제본마다 데이터베이스 ID는 새로 생기지만 속성 이름과 선택지, 페이지 본문 구조는 같습니다. 이 스킬은 그 구조를 알고 있는 팀원처럼 동작합니다.

## 요구 사항

- **Claude** — Cowork, Claude Code, 또는 Agent SDK
- **Notion MCP 연결** — 페이지 조회·생성·수정 권한
- **대상 프로젝트** — 위 템플릿으로 만든 Notion 프로젝트. 업무 DB에 `이름` / `진행 상황` / `날짜` 속성이 있어야 합니다

> 이 스킬은 **위 템플릿 구조 전용**입니다. 구조가 다른 Notion 워크스페이스를 자동으로 인식하거나 맞춰주지 않습니다. 스키마가 맞지 않으면 규칙을 억지로 적용하지 않고 그 사실을 알리고 멈춥니다.

## 설치

**Cowork** — `.skill` 파일(이 폴더를 압축한 것)을 열고 "스킬 저장"을 누릅니다.

**Claude Code / Agent SDK** — 이 폴더를 스킬 디렉터리에 복사합니다.

```bash
git clone https://github.com/tacocat404/notion-project-logger.git
```

## 사용법

이름을 부르지 않아도 됩니다. 업무를 추가하거나, 상태를 옮기거나, 일을 마무리하거나, 대화를 기록하거나, 새 프로젝트를 시작할 때 스킬이 알아서 나섭니다. "Notion"이라는 단어가 나오지 않아도, 데이터베이스 ID가 다른 새 복제본이어도 동작합니다.

```
"로그인 API 구현 업무 등록해줘"
"그거 지금 막혔어, 서버 응답을 기다리는 중이야"
"다 했어, 정리해줘"
```

## 워크플로

| # | 이름 | 하는 일 |
|---|---|---|
| 0 | 프로젝트 성격 진단 | 기획서·요강·설명을 읽고 이 프로젝트가 뭔지 파악해 단계·속성·폴더 구성을 제안. **유형별 프리셋 없음** |
| 1 | 업무 등록 | 동사형 이름·진행 상황·날짜를 갖춰 업무 생성. **작업 단계 하나 = 업무 하나**, 프로젝트 전체는 상위 업무로 |
| 2 | 진행 중 업무 수정 | 진행 메모 / 진행 상황 / 업무 로그 세 갈래를 구분해 기록 |
| 3 | 완료 의식 | 결과 & 인사이트 → 산출물 정리 → 완료 표시. 표시만 하고 앞의 둘을 건너뛰지 않게 함 |
| 4 | 새 프로젝트 세팅 | 목표 옵션에 맞춰 자료실 생성, 팀원별 개인 폴더, 완료 업무 정렬 뷰 |
| 5 | 개인 작업 일지 | 개인 폴더에 육하원칙 기록. 시간순 원본 + 단계별 정리본. 체크포인트에 모아서 작성 |
| 6 | GitHub 사본 점검 | 주 1회 저장소 사본과 실행 중인 스킬의 차이를 확인해 **보고만** |
| 7 | 템플릿 성장 | 구조가 실제 일하는 방식과 어긋나는 신호가 쌓이면 개편을 **제안**. 적용은 관리자 승인 후 |

## 동작 원칙

**스킬은 해석기, 가이드 문서가 설정입니다.** 스킬은 "가이드를 읽고 거기 적힌 대로 한다"는 절차만 갖고, 어떤 단계·속성·폴더가 있는지는 전부 그 프로젝트의 「프로젝트 관리 템플릿 사용 가이드」에서 읽습니다. 그래서 프로젝트가 자라도 스킬 파일은 그대로이고, 서로 다르게 자란 프로젝트들을 **하나의 스킬로** 담당할 수 있습니다.

**ID도 옵션 값도 하드코딩하지 않습니다.** 복제본마다 데이터베이스 ID가 다르고, 자란 프로젝트마다 목표·진행 상황 옵션도 다릅니다. `references/notion-schema.md`의 ID는 전부 자리표시자이고, 옵션 목록은 "새 복제본의 출발값"일 뿐입니다. (대화당 프로젝트별 1회만 조회하고 그 세션 동안 재사용합니다.)

**대회 유형별 프리셋을 만들지 않습니다.** "AI 대회용 세트" 같은 걸 미리 넣어두면 결국 고정된 칸에 현실을 밀어 넣는 같은 문제를 이름만 바꿔 반복하게 됩니다. 매번 그 프로젝트의 자료를 읽고 도출합니다. 새 복제본에 들어있는 목표 6종도 "검토 대상"이지 기본값이 아닙니다.

**개인의 판단을 대신 쓰지 않습니다.** 결과 & 인사이트, 회고, "공부한 내용" 같은 본인 성찰 항목은 지어내지 않습니다. 초안을 제안하는 선까지만 하고 본인 확인을 받습니다. 반면 대화에서 실제로 일어난 일의 기록은 확인 없이 바로 적습니다 — 그 둘은 다릅니다.

**업무 로그는 사람이 씁니다.** 팀 공유 채널의 주인은 사람입니다. 스킬은 "이거 팀에 공유할 만한데요"라고 알려주기만 하고, 스킬이 쓰는 기록은 개인 폴더로 갑니다.

**남의 업무를 건드리지 않습니다.** 다른 사람이 담당인 업무의 진행 상황은 바꾸지 않고 댓글을 남깁니다.

**구조를 혼자 바꾸지 않습니다.** 폴더 추가처럼 덧붙이는 일은 바로 하지만, 속성·옵션 재편처럼 팀 전체에 영향을 주는 변경은 근거와 영향 범위를 보여주고 승인을 받은 뒤에 합니다.

**스스로를 덮어쓰지 않습니다.** Workflow 6은 저장소 사본과 실행 중인 스킬의 차이를 알려줄 뿐, 원격에서 받아온 내용으로 스킬을 자동 갱신하지 않습니다. 동기화 여부는 사람이 판단합니다.

## 저장소 구조

```
notion-project-logger/
├── SKILL.md                        스킬 정의 — 이름, 실행 조건, 워크플로 0~7
├── README.md
├── LICENSE
└── references/
    ├── notion-schema.md            데이터 구조 — 고정부/가변부를 나눠 서술
    └── template-rules.md           공식 가이드 규칙 요약 — 대비용
```

`references/template-rules.md`는 **대비용**입니다. 프로젝트의 실제 가이드 페이지를 찾을 수 없을 때만 쓰고, 그 경우 사용자에게 알립니다.

`references/notion-schema.md`는 **고정부**(모든 복제본이 공유하는 뼈대)와 **가변부**(프로젝트마다 다르고 자라면서 바뀌는 값)를 나눠 적습니다. 가변부에 적힌 목록은 참고용 출발값일 뿐이고, 실제 값은 그 프로젝트의 가이드와 데이터베이스에서 읽습니다.

## 만들게 된 계기

팀 프로젝트에 관리 템플릿과 가이드를 만들어두어도, 팀원들이 그걸 그대로 따르게 만드는 건 다른 문제였습니다. 규칙을 지키라고 계속 상기시키는 대신 **행정적인 기록을 대신 처리해주는 쪽**으로 방향을 잡은 것이 이 스킬의 출발점입니다. 팀원들이 대화하며 일하는 동안, 누가 무엇을 하고 있는지가 따로 묻지 않아도 드러나게 하는 것이 목표였습니다.

Claude 스킬은 **재사용 가능한 작업 매뉴얼**에 가깝고, 필요한 만큼만 단계적으로 읽히는 구조입니다 — 이름과 설명은 항상, 본문은 호출될 때, `references/`는 실제로 그 내용이 필요할 때. 그래서 판단 기준은 `SKILL.md` 본문에, 상세한 스키마와 규칙 요약은 참고 파일로 나눠 담았습니다.

워크플로는 한 번에 나오지 않았고, 실제 워크스페이스에서 업무를 등록하고 수정하고 보류했다가 재개하고 완료 처리하는 흐름을 돌려보며 다듬었습니다. 그 중 가장 크게 뒤집은 것이 Workflow 6입니다. 처음에는 GitHub 내용으로 스킬을 **자동 갱신**하게 해두었는데, 저장소가 뒤처져 있을 때 새로 만든 기능을 그대로 지워버릴 뻔했습니다. 그 뒤로 자동 덮어쓰기를 걷어내고 차이를 보여주기만 하도록 바꿨습니다.

두 번째 큰 개정은 실제 AI 대회에 써 보고 나왔습니다. 업무는 2건뿐인데 업무 로그에는 EDA·검증 설계·모델 학습·보정·패키징 6건이 **성격이 안 맞는 업무 하나에 전부 매달려** 있었고, 자료실과 개인 폴더는 텅 비어 있었습니다. 원인은 두 가지였습니다 — 목표 옵션에 그 작업들에 해당하는 칸이 아예 없었고(고정된 칸에 현실을 밀어 넣은 것), 정작 스킬은 팀 공유 채널에 기술 로그를 쌓고 있어 개인 기록은 아무도 안 쓰고 있었습니다. 그래서 **구조가 프로젝트에 맞게 자라도록**(Workflow 0·7) 하고 **기록의 주인을 다시 나눴습니다**(업무 로그는 사람, 개인 폴더는 스킬).
